## Remaining implementation comparisons

**#471, polling:** in a temporary repository, commit file A, stage B, restore working content A; then stage C and restore working content A. Both `git diff HEAD --unified=0 --no-renames --no-color --no-ext-diff` signals are identical, and the untracked list and HEAD are unchanged. The working diff changes from B→A to C→A, so the proposed worktree poller misses a real working-mode change. It also bypasses the fork’s Git-client factory and logs diagnostics on stdout. The independent repository-membership optimization is useful and does not require the polling rewrite.

**#475, multiple repositories:** the proposal wraps fetch/EventSource globally and changes the active repository on tab selection. The mounted watch subscription remains connected to its original repository; the switch handler does not recreate it. Conversation, approval, named capture and authorized editor state would also need per-repository identities throughout the fork. The proposal is not a compatible replacement for that state.

**#485, rendered Markdown comments:** `handleSubmitComment` takes only the body and loses the form’s intent options; the preview’s thread-card props omit the fork’s resolve/reopen and restore callbacks. Its default switches from Code Diff to Split Preview, reversing the commenting default retained after #207/#208. Preserve the current code/preview boundary and immutable-capture restrictions rather than replace them with this implementation.
